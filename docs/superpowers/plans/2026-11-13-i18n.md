# i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** UI, voice alerts, voice commands, TTS/STT, Claude output and PDF follow a language picked from a title-bar dropdown (de/en/es/fr/it), switching immediately.

**Architecture:** i18next with one JSON file per language in `src/shared/locales/`, loaded by two instances: one in the renderer (`react-i18next`) and one in main (`i18next.createInstance()`). The `language` key in `app_config` is the single source; main initialises it from the system language on a fresh DB. Claude prompts become a single English source plus a per-language "Output language" block; setup parameter/category names become English data keys localised only at display.

**Tech Stack:** Electron, React 19, Zustand, react-bootstrap, i18next, react-i18next, TypeScript 6 strict, assert-based self-checks.

**Spec:** `docs/superpowers/specs/2026-11-13-i18n-design.md`

## Global Constraints

- Languages, in dropdown order: `de` Deutsch, `en` English, `es` Español, `fr` Français, `it` Italiano (native names, alphabetical).
- BCP-47 locales: `de-DE`, `en-GB`, `es-ES`, `fr-FR`, `it-IT`. English flag = Union Jack.
- Default on a DB without `language`: first match of `app.getPreferredSystemLanguages()` on the 2-letter prefix, else `en`. `fallbackLng: "en"`.
- Dictionary files: `src/shared/locales/{de,en,es,fr,it}.json`, single namespace `translation`, nested keys, i18next interpolation `{{var}}`, plurals `_one`/`_other`. `it.json` is the type source (`CustomTypeOptions`).
- No compatibility with existing DB data: the user resets the DB after implementation. No migrations, no legacy Italian matching.
- `<sintesi-vocale>` tag, `##`/`###`/`####` heading hierarchy and the wording rules (no procedure names, no all-caps words except acronyms) are unchanged and apply in every language.
- Flags are inline SVG (Windows does not render flag emoji).
- Code style: arrow functions, no `class`, named exports, `type` over `interface`, relative imports, Ponytail. Italian comments keep real accents.
- Gate after every task: `npm run typecheck && npm run lint && npm run format:check && npm run selfcheck && npm run fallow:check`. Never commit without the user's explicit OK (user rule): each "Commit" step means *stage and ask*.
- Domain skills for implementers: renderer tasks → `react-vite-best-practices`; main/IPC tasks → `electron-best-practices`; prompt tasks → `claude-api`.

## Review Focus

1. **Switching language mid-session while a `listenAgain` setup-name prompt is pending** → the answer is still consumed as a name, and the next spoken line is in the new language. (Task 7 test.)
2. **Saved Azure voice from another language** (`azureVoiceName_it` set, language switched to `de` with no `azureVoiceName_de`) → synthesis uses the default German voice, never an Italian voice reading German. (Task 6 test.)
3. **System locale with region or an unsupported language** (`it-CH`, `de-AT`, `pt-BR`, empty list) → `it`, `de`, `en`, `en`. (Task 1 test.)
4. **A translation that drops or renames an interpolation variable** → caught by `locales.selfcheck.ts`, not at runtime as a literal `{{n}}` spoken by the TTS. (Task 1 test.)
5. **A setup lever whose English name no `LEVERS` regex matches** → the ladder step silently becomes "non valutabile". Every game's lever names are asserted against `LEVERS`. (Task 3 test.)
