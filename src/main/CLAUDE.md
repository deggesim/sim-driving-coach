# Main process (`src/main/`)

Loaded when working under `src/main/`. Architecture-wide decisions live in the root `CLAUDE.md`.

- **main.ts** — Electron entry point; wires IPC handlers, owns the three readers (`R3EReader`/`AceReader`/`Ams2Reader`) but runs them ON DEMAND — one at a time, only during a session (or briefly while probing at start/reopen); idle = zero SHM polling. `insertSetup` è l'unico punto di scrittura dei setup (handler UI, riuso e comando vocale passano da lì, così il push `session:setupLoaded` e l'attivazione non divergono). Accanto a `pendingGame` c'è `pendingSetup`: entrambe le attese di una risposta parlata scadono dopo `PENDING_ANSWER_TTL_MS`. `startSession`/`session:reopen` are async: they call `awaitReaderReady(game, ~3s)` (start reader → wait for live frames + car/track, else `not-live`/`no-data` error), and `closeSession` calls `stopAllReaders` (stop reader + clear car/track globals). `readerRunning` tracks the single active reader; `startReader`/`stopReader` keep it in sync. `activeGame` is the game the user picks at session start (`session:start` takes a `GameSource`); while idle it holds the last picked game. Connection state is frame-recency based (`isLive(game)` = frame within `LIVE_STALE_MS`; a `liveTicker` re-pushes status so a closed sim drops off the badges). No auto-priority selection. `announceStintReady()` (called from `lapRecorded`, after `zones_json` is patched) speaks `sessionCoach.stintReady()` via `speakText` once per `(game, session, setup_id)` key — the cue to pause and run "Esegui analisi"; Azure TTS only, no Web Speech fallback
- **preload** (`src/preload/index.ts`) — Context bridge exposing `window.electronAPI` to renderer. Compiled as CJS by electron-vite (required by `sandbox: true`)
- **game-adapter.ts** — Projects R3EFrame → GameFrame (unified 7-field struct: lapDistance, tcActive, absActive, brakeTemps FL/FR/RL/RR). ACE and AMS2 readers emit GameFrame natively
- **input-manager.ts** — Global push-to-talk key via a `WH_KEYBOARD_LL` hook (koffi → user32), **not** Electron `globalShortcut`: a `RegisterHotKey` hotkey is not delivered while a sim holds the foreground (verified with RaceRoom, fullscreen and borderless — neither main nor renderer saw the trigger). Fires `onInputTrigger` to the renderer on key-down and never consumes the event (the sim still receives the key, unlike `globalShortcut`); key repeat is ignored until key-up. Non-Windows stub returns no-ops
- **key-combo.ts** — Pure parsing of the stored shortcut format (`event.key` + `Ctrl/Alt/Shift` prefixes joined by `+`, parsed greedily so `Ctrl++` works) and the named-key → virtual-key table (F1-F24, arrows, Space…). Single characters are left to `VkKeyScanW` because their VK is layout-dependent. Dependency-free so `key-combo.selfcheck.ts` can assert it
- **lap-recorder.ts** — Attaches to reader, aggregates frames into 50m zones with driving metrics, handles 2-lap calibration phase. `aggregateZones` is exported for `lap-recorder.selfcheck.ts` and decides **per channel** whether an extended field is emitted — never one flag for the whole block
- **ladder-counters.ts** — Pure per-zone event counts for the setup ladder (`ladderCounters(frames, zoneOf)`: hard-brake/ABS frames, wheel locks per axle, nervous downshifts, exit wheelspin asymmetry, under/oversteering corners (oversteer in every phase = counter-steer, `str·gLat` against the corner's majority sign on > 15 % of the phase frames: an entry/exit `k` ratio rises from yaw lag alone), plus slow (<100 km/h) / fast (>120 km/h) corner counts with mid-corner balance — the same under/oversteer detectors on both classes, `cornersFastUnder/Over` feed area 8 — and `k` sums), spread into `ZoneData` by `aggregateZones`. Presence per family: brake counts always, `sr` family only on zones whose frames carry `sr` (`srHardBrakeFrames` = the hard-brake frames that carry slip, the denominator of the lock share in the ladder), corner family only on zones where a corner starts and only if the lap has `gLat`. A downshift or corner belongs to the zone of its first frame. Thresholds are named constants at the top; asserted by `ladder-counters.selfcheck.ts`
- **chassis-counters.ts** — Pure per-zone chassis events for the setup overview (`chassisCounters(frames, zoneOf)`, spread into `ZoneData` by `aggregateZones` like `ladder-counters`): bottoming events per axle and phase (braking / mid-corner / fast straight, plus "upset" touches that unsettle the car), ride-height sums, `loadFit` regression sums of wheel load against speed² (the input of `weight-distribution.ts`), suspension oscillations and straight-line steering reversals. Bottoming is also split per phase and axle (`straightFront/Rear`, `upsetFront/Rear`), so areas 3 and 4 name the axle of their own phase; the straight/mid-corner ride-height sums use the axle **mean** (roll alone opens no gap), the minimum keeps the lower wheel. Suspension **velocity is derived from the travel `sus` for all three games by choice** (one method for the three; R3E maps `Player_SuspensionVelocity`, ACE has none). A lap whose median axle-mean `rh` is outside 5–300 mm (all zeros included) counts as absent. Thresholds are named constants at the top; asserted by `chassis-counters.selfcheck.ts`
- **channel-log.ts** — Smoke-test logging for `CompactFrame`'s extended channels
  (`logChannels(tag, frame)`, called by the three readers). Prints "absent" and
  "all zeros" as words rather than numbers, so a missing channel cannot be
  confused with a wrong offset. One line per game on the first moving frame;
  `SDC_CHANNEL_LOG=1` keeps a line coming every ~2s; it also prints `alt=…mm carico=…N` (ride height, wheel load). `formatChannels` is pure and
  asserted by `channel-log.selfcheck.ts`
- **zone-tracker.ts** — Stateful tracker for current 50m zone during a lap (feeds RuleEngine real-time checks)

## Per-game channel coverage

`CompactFrame`'s extended channels are filled in per reader: a game that cannot
supply one omits it, and `aggregateZones` decides presence per channel, so a
missing channel never reaches a prompt as a zero.

| Channel | R3E | ACE | AMS2 |
| --- | --- | --- | --- |
| `rpm` | `EngineRps` (rad/s → RPM) | `rpms` | `mRpm` |
| `gLat` / `gLon` (g) | `Player_LocalGforce_X` / `_Z` (already g) | `accG[0]` / `accG[2]` | `mLocalAcceleration[0]` / `[2]` ÷ 9.80665 |
| `tp` (PSI, stored) | `TirePressure` kPa × 0.145038; the whole quartet is dropped when any wheel reads -1 (= N/A) | `wheelsPressure` | `mAirPressure` × 0.145038 (despite `SharedMemory.h` documenting it as PSI, the raw value is kPa — confirmed by comparing a session's first-lap reading against the setup's cold bar pressure) |
| `sr` | derived: `(-TireSpeed - CarSpeed) / CarSpeed` (TireSpeed is negative rolling forward, verified live), zeroed below 5 m/s | `slipRatio` | — derived from `mTyreRPS` (rad/s) with a tyre radius estimated in pure rolling (median of 100 samples, redone on every reader start); absent until estimated |
| `sus` (m) | `Player_SuspensionDeflection` | `suspensionTravel` | `mSuspensionTravel` |
| `rh` (m) | `Player_RideHeight` double[4], **assumed metres**, not verified live; a quartet with any value < 0 is dropped | `rideHeight[2]` @268, **per axle**, mapped to `[F, F, R, R]` (a touch must count once per axle, not twice) | `mRideHeight` @20380 in cm, ÷ 100. Not in pCARS2 `SharedMemory.h`: an AMS2 addition taken from AMS2SharedMemoryNet `AMS2Page.cs`, **not verified** |
| `wl` (N) | `TireLoad`, same dropping rule | `wheelLoad` @72 | — absent |
| `fuel` (L) | `FuelLeft` | `fuel` @12 | — absent (fuel is used only for R3E/ACE) |
| `tt` (°C) | `TireTemp_*_Center` | `tyreCoreTemperature` | `mTyreTemp` |
| `tti` / `ttc` / `tto` (°C) | `TireTemp_*_Left/Center/Right`, oriented via `leftRightToInnerOuter` ("left" = outer on left wheels, inner on right wheels; **assumed**, to confirm on a long corner) | Graphic page `SMEvoTyreState` left/center/right (`GFX_TYRE`, in-struct offsets 24/28/32; +8/+12 verified live against pressure/carcass), oriented via `leftRightToInnerOuter` like R3E: left/right are the wheel's physical sides, **not** inner/outer as the spec text says (Lotus data: outer shoulder ~2 °C hotter on all four wheels only under that reading; confirm with a camber change). The physics `tyreTempI/M/O` @368/384/400 read all zeros on 0.9.1, so they are not used | `mTyreTempLeft/Center/Right` @20328/20344/20360, same orientation as R3E, **not verified** |
| `at` / `rt` (°C) | — | `PHY.airTemp` / `PHY.roadTemp` | `mAmbientTemperature` / `mTrackTemperature` |
| `rain` / `wind` / `cloud` | — | — | `mRainDensity` (0-1) / `mWindSpeed` (m/s) / `mCloudBrightness` (0-1). `mWindDirectionX/Y` not surfaced — a raw heading component isn't actionable without the track's own heading, which the SHM doesn't expose |

`tp` stays PSI in storage/`channel-log` for all three games so `session-stats.ts`
never needs to know which game it is averaging. Display is a separate concern:
`prompt-builder.ts` (`pressureUnit()`) converts it back to bar only in the text
sent to Claude for AMS2, whose in-game UI shows bar (R3E and ACE display PSI,
matching what's already stored) — the raw channel and the other two games are untouched.

None of the `rh` / `wl` / `fuel` offsets or units has been checked live yet: the `channel-log` line prints `alt=…mm carico=…N`, which should read tens of mm falling under braking and at speed, and four wheel loads summing to about mass × 9.81 at low speed. An `rh` whose lap median (axle means) is outside 5–300 mm — all zeros included — counts as absent (wrong offset or unit), never as a zero ride height.

Two traps worth remembering: AMS2's `mSuspensionTravel` (7340) and `mAirPressure`
(7372) are declared **after** `mSequenceNumber` (7320) in `SharedMemory.h`, so
their offsets legitimately sit past it; and R3E's and AMS2's slip ratio is derived, not
measured, so confirm it against the sim before trusting a value.

**Smoke-testing the channels** — `channel-log.ts` is called from all three
readers right after each `lapFrames.push`. On the first frame above 30 km/h it
prints one `[R3E]`/`[ACE]`/`[AMS2] canali …` line, which is the coverage check:
an unfilled channel reads `assente`, an all-zero quartet (the usual signature of
a wrong offset) reads `zeri`, so neither can be mistaken for a measurement. For
a continuous trace every ~2s while driving, start with
`$env:SDC_CHANNEL_LOG=1; npm run dev`. Expected magnitudes: G 1-2, pressures
20-30 PSI, suspension travel tens of mm, slip |0.02-0.15| — a slip ratio pinned
at 0.000 means `TireSpeed` is not the circumferential speed assumed here, and G
values swapped between `gLat` and `gLon` mean the axis mapping is wrong.

## `r3e/`

- **r3e-struct.ts** — R3E shared memory struct layout (`VERSION_MAJOR = 3`; `STRUCT_SIZE_KNOWN` ≈ 2012 bytes, mapped through `NumCars` — `DriverData[128]` is deliberately not mapped), Pack=4 alignment, auto-computed offsets, read helpers
- **r3e-reader.ts** — Opens `$R3E` via `koffi` + kernel32.dll, polls at 16ms, emits `frame`, `lapComplete`, `connected/disconnected`. Auto-enters mock mode on non-Windows
- **r3e-data-loader.ts** — Loads `r3e-data.json` from the R3E Steam install; resolves numeric IDs → display names for car, track, and layout. Used in prompts and UI; DB always stores numeric IDs for R3E

## `ace/`

- **ace-reader.ts** — Opens three ACE SHM pages (PhysicsEvo 800B, GraphicsEvo 3940B, StaticEvo 256B) via koffi at 16ms. Emits GameFrame + CompactFrame (with ACE-only fields: rpm, gLat, gLon, tyre pressures, slip ratios, suspension travel, inner/centre/outer surface temperatures from the Graphic page `SMEvoTyreState`, offsets verified live). Car/track/layout are readable strings from SHM (e.g. `"ks_porsche_718_gt4"`, `"monza"`). Lap completion detected via `totalLapCount` increment. Mock fallback on non-Windows. **SHM spec:** https://docs.google.com/document/d/1WzqMLkW2o_C0LGcvdMRelAV31ZIifux0CSHD9k6ddz0/edit?tab=t.0
- **ace-struct.ts** — Struct definitions for all three ACE SHM pages with read helpers
- **ace-setup-reader.ts** — Decodes binary protobuf `.carsetup` files from `D:\Salvataggi\ACE\Car Setups\{car}\{track}\`. Extracts setup params (steering ratio, brake bias, ARBs, dampers, geometry, electronics, aero, fuel, compound). Returns `SetupData` with Italian-labelled params. **Spec:** `ace_carsetup_spec.md` (local, reverse-engineered)

## `ams2/`

- **ams2-reader.ts** — Opens the single SHM page `$pcars2$` via `koffi`, polls at 16ms. Reads `mSequenceNumber` before and after copying the buffer to detect torn reads (atomic snapshot); frozen sequence number for ~2s while playing → disconnect. Derives `sr` via `createSlipEstimator` (`ams2-slip.ts`: radius self-calibrated in pure rolling, reset in `start`; the reader logs one `raggio ruota calibrato` line when the radius becomes available — the `canali` smoke line fires earlier and reads `slip=assente` until then). Emits GameFrame natively + `lapComplete` (via `mLapsCompleted` increment). Car/track/layout are readable strings from SHM. Mock fallback on non-Windows
- **ams2-setup-vision.ts** — Decodifica dei setup AMS2 dalle schermate via Claude Vision (`claude-sonnet-5`), l'unico import setup che passa da un modello. Esporta `resolveAms2ScreenshotsDir()` (auto-detect dell'account Steam → cartella screenshot, appid `1066890`), `listAms2Screenshots(dir)` (nome + `mtimeMs`, dal più recente — ordinato per `mtime` e non per nome, che è cronologico solo finché Steam timestampa i file; nessuna thumbnail, le costruisce `setup:listScreenshots`) e `decodeAms2Setup(...)`. Due chiamanti — l'handler `setup:decodeSetup` e il comando vocale "acquisisci setup" — quindi il system prompt di OCR vive qui e non in `main.ts`
- **ams2-struct.ts** — pCARS2 `SharedMemory` struct layout (`SHARED_MEMORY_VERSION = 14`), Pack=4 alignment, offsets derived from `SharedMemory.h`. Validated by `ams2-struct.selfcheck.ts` (run via `npm run selfcheck`)
- **ams2-cars.ts** — **Generated** (`npm run update:ams2-cars` → `scripts/update-ams2-cars.mjs`): 208 cars from the community sheet "Cars of AMS2" (name, weight, front weight share, driveline, differential type). Never edit by hand; listed in `.prettierignore` and in `.fallowrc.json` `ignorePatterns`. The script rejects a weight outside 100–6000 kg
- **ams2-car-lookup.ts** — `findAms2Car(name)`: the table row for the car named by the SHM, or `null`. Names are normalized (lowercase, accents folded, punctuation → space); a name shared by rows that differ (9 of them) is ambiguous and also returns `null`, so a caller must treat `null` as "unknown car", never guess. Asserted by `ams2-car-lookup.selfcheck.ts`

## `coach/`

- **adaptive-baseline.ts** — EMA (alpha=0.3) baseline per zone, detects deviations (LATE_BRAKE, SLOW_THROTTLE, TRAIL_BRAKING, COASTING, BRAKE_THROTTLE_OVERLAP), persists to SQLite. Game-aware (R3E/ACE/AMS2) — queries the per-game table (`baseline_r3e`/`baseline_ace`/`baseline_ams2`, resolved via a `_${game}` suffix, not a `game` column)
- **rule-engine.ts** — AlertDispatcher (priority queue, P1>P2>P3, dedup per zone/type/lap, 4s silence window) + RuleEngine (frame-level P1/P2, post-lap P3)
- **session-coach.ts** — On-demand session analysis engine (`createSessionCoachEngine`). Also exposes `stintReady(sessionId, game)` (the "stint analizzabile" phrase or `null`, no API call, built on the same loader and now through `computeSessionStats`, so it sees the overview too; it also computes the stats before the last counted lap — `minJudgedLaps: 1` — as the `prev` of `stintReadyMessage`). Exposes three entry points sharing one loader (`loadSessionBundle`: session + laps + setups + prior analyses + `leaderboardMode`/`fixedSetup`, which it derives from the session row — it is the **single source** for those two flags, no caller passes them in): `analyzeSession` (Level 1 — non-streaming `messages.create`, `max_tokens: 2000`, writes `synthesis` + `summary`), `expandAnalysis` (Level 2 — non-streaming `messages.create` too, `max_tokens: 32000`, `UPDATE … SET detail`, optional `modelOverride` = `anthropicModelDetail`), and `commentAnalysis`. Neither level streams: both fire `onStart({ sessionId, version })` once (→ `session:analysisStart`) so the renderer can hold a spinner, then deliver the whole text via `onDone`. Multiple analyses per session (incremental version counter). Extracts the `<sintesi-vocale>` block (max 3 sentences) into `summary` for TTS and strips it from the rendered text. Tutti e tre i punti di scrittura passano il testo del modello da `decodeAlertCodes` (`shared/alert-types.ts`) **prima** di salvarlo — in `analyzeSession` prima di `stripVoiceTag`/`extractVoiceSummary`, così nemmeno la sintesi letta dal TTS può contenere una sigla ereditata da un'analisi precedente.
- **prompt-builder.ts** — Builds the Claude prompts from session data + laps + setups + deviations + corner names + the precomputed stats block. Exports `buildSynthesisPrompt` / `SYNTHESIS_SYSTEM_PROMPT` (Level 1 — named after the `synthesis` column, deliberately **not** "summary", which in this codebase means only the `<sintesi-vocale>` TTS extract), `buildSessionPrompt` / `SESSION_SYSTEM_PROMPT` (Level 2), `buildCommentPrompt` / `COMMENT_SYSTEM_PROMPT`, plus `buildStatsBlock` and `getSignificantZones`
- **session-stats.ts** — Computes the authoritative numeric facts in TypeScript (lap deltas, convergence, alert counts, aid durations, plus the per-corner steer/G/tyre-pressure/tyre-temperature/slip/suspension channels, each averaged over the laps that actually carried it) and injects them as a "## Dati Calcolati" block. `ComputeStatsInput.game` / `car` feed `SessionStats.setupOverview`; its "Assetto telaio" lines (the overview) are printed only when `lapsMissing === 0`, and Level 2 gets a `### Assetto telaio` subsection (Level 1 proposes a single action on the overview's current area once the ladder is complete). The system prompts instruct Claude to **cite** these numbers, never recompute them — the only figure it may estimate is the seconds/lap impact
- **setup-ladder.ts** — `computeSetupLadder(laps, setupLabelById, { fixedSetup, leaderboardMode })`, pure: judges the six setup-ladder steps (ducts → bias → engine braking → pressures → camber → differential) on the judged laps of the last setup segment (valid laps whose mean tyre temperature moved ≤ 2 °C from the previous lap — the carcass `avgTyreTempC`, else the centre surface: ACE's surface centre swings 36-125 °C within a lap and never settles, its carcass does — ≥ 2 needed — **no fixed lap floor**, so a pit stop drops laps until the tyres are back at temperature; without tyre temps, or in Leaderboard where they are fixed at 85 °C, it falls back to the old "from the 4th lap"; `lapsMissing` is `max(0, 2 − judged)`, a lower bound) by summing the `ladder-counters` fields of `zones_json`; a field absent everywhere gives `na` with a reason. Step 1 (brake ducts) is judged on its own laps instead — every lap of the segment after the out-lap, valid or not, no tyre plateau (`ductsLaps`) — so with laps still missing `steps` holds step 1 alone, current once it has ≥ 2 such laps and needs a fix. With `opts.setupParams` (the setup on the last segment) a `fix` step whose lever (`LEVERS`, matched on the parameter name across the three games) is missing becomes `na` "leva non presente nel setup caricato — …" and `current` moves on (on AMS2 only when the setup holds a parameter of the step's Vision category, `AMS2_LEVER_PAGES`, since the screenshots may skip a page); without a loaded setup nothing changes. On R3E (`opts.game`) the fixes of steps 2, 4 and 5 carry `moves` (the R3E parameter and `up`/`down`: Brake Bias up = toward the rear, Brake Pressure down, Tyre Pressure per wheel, Camber per wheel down = more negative); when every move present in the setup is blocked by its `limit`, the step becomes `ok` "… — già a fondo scala". The shared check is the exported `blockedAtLimit(alternatives, params)` (alternatives ORed, moves inside one needed together); `setup-overview.ts` uses it too: its fixes carry `moves` and, on R3E with `setupParams`, a blocked fix turns into a datum "…: già a fondo scala". Differential and coast stay out: R3E lock % and AMS2 ramp angles have no single direction. The bias step's lock share uses `srHardBrakeFrames` as denominator (not `hardBrakeFrames`); the pressures step names the axle with the largest |Δ| (tie → front) and lists only its out-of-tolerance wheels, so the model never picks the axle. Thresholds are named constants at the top; exposed as `SessionStats.setupLadder` (always computed; with `leaderboardMode` steps 4-5 are `na` — "gomme fisse a 85 °C (Leaderboard)" — and `tyres` is empty; on ACE (`ladderFlags` → `camberUnreadable`) step 5 is `na` and `TyreSummary.innerMinusOuterC` is `null`, because the sim's shoulder temps differ by ~1 °C even at -3° camber, as also seen in MoTeC), asserted by `setup-ladder.selfcheck.ts`. `computeSetupLadder` also takes `opts.car` (AMS2, from `findAms2Car`): FIXED / SPOOL / OPEN differentials make step 6 `na` "differenziale non regolabile", and G-LSD / GC-LSD use the bias-ratio wording. `stintReadyMessage(ladder, overview?, prev?)` builds the phrase spoken once the stint has ≥ 3 counted laps (`READY_JUDGED_LAPS`; counted = `ductsLaps` while step 1 is current before the judged laps, else the judged laps), or 2 when `verdictKey` (state and reason, numbers blanked, of the steps up to the current one and — ladder complete — the areas up to the current one) equals that of `prev`, the stats before the last counted lap; with step 4 current always 3 (pressure drift). The phrase: the count plus the first step to fix, or "nessun passo da correggere" (with an `overview`, once the ladder is complete it names the current area instead); `null` otherwise. `opts.minJudgedLaps` (default 2) lowers the judged-lap floor, used only for that `prev`
- **setup-levers.ts** — `extractSetupLevers(params, game)`: springs and the four damper families (bump / rebound, slow / fast), each either all four wheels or absent, from the Italian-labelled `SetupParam[]` of the three games. The AMS2 Vision prompt is given canonical parameter names (`buildAms2SetupSystemPrompt`, `AMS2_CANONICAL_PARAMS`) so the extractor can match them; the list also carries the setup-ladder lever names ("Condotti freni", "Bilanciamento freni", "Pressione FL…", "Camber FL…", "Coast ramp", "Power ramp", "Precarico"…) matched by `setup-ladder.ts`. The R3E damper labels are not confirmed on a real export yet. Asserted by `setup-levers.selfcheck.ts`
- **weight-distribution.ts** — `weightDistribution(game, zones, car)`: R3E and ACE are **measured** from the wheel-load regression (intercept = static load, slope = aero load; needs ≥ 300 samples, ≥ 20 of them below 120 km/h to anchor the intercept, taken from **every lap of the session** since the static split does not depend on the setup; the aero share is reported only when it is ≥ 1 % of the static load and both axle slopes are ≥ 0); AMS2 reads the table row from `findAms2Car`. Degenerate input (too few samples, one speed, loads ≤ 0, unknown car) gives "sconosciuta" with a reason, never `NaN`; so does a measured front share outside 30–70 % ("distribuzione misurata non plausibile"). Asserted by `weight-distribution.selfcheck.ts`
- **setup-overview.ts** — `computeSetupOverview(...)`, pure: the "quadro assetto", eight areas judged in TS from the Frezza guides (molle, altezze e rake, bumpstop, terze molle, ammortizzatori, barre antirollio, convergenze, aerodinamica), each `ok` / `da correggere` / `na` with the figure behind it. **One symptom, one owner**: a symptom belongs to a single area and the others cite it as "vedi area N". Springs are judged against the exact weight ratio (target ratio = front share ÷ rear share, 289 and not Frezza's rounded 288) and carry a "molle non verificate" suffix when the setup could not be read in full; dampers are "uniform" within one click (the R3E/ACE defaults differ by one front-to-rear); the bumpstop uses touches per **judged** lap; area 2 is `na` without ride height (spec §2 wins over the plan) and entry understeer is left to rake only when ABS is not dominant (otherwise it belongs to ladder step 2, spec §2). Areas 3 and 4 name the axle from the touches of their own phase (upsetting / fast straight), and area 4 never says "ammorbidire" when it already says "irrigidire". Area 8 compares the mid-corner symptom of fast and slow corners (under/over in more than half of the fast ones and at most half of the slow ones), not the `k` ratio, which is the understeer gradient. A recording made before the chassis fields existed (`zones_json` without them) makes the telemetry-judged areas `na` with the reason, while molle and the setup half of ammortizzatori can still be judged from the loaded setup. The overview names a **current area** only when the ladder has no current step and no laps are missing; `judgedLapsOfLastSegment` is exported from `setup-ladder.ts` for it. Thresholds are named constants at the top; exposed as `SessionStats.setupOverview`, asserted by `setup-overview.selfcheck.ts`
- **spoken-name.ts** — `normalizeSpokenName(text)`: la trascrizione del nome di un setup dettato a voce (R3E e AMS2 lo chiedono, ACE prende il nome del file) → il nome vero. Lettere compitate in italiano o inglese ("vu uno", "em fourteen") → caratteri minuscoli, numeri a parole → cifre, nomi di simboli ("trattino basso", "underscore", "spazio") → simboli. I nomi di lettera che sono anche parole correnti ("di", "ci", "e", "you") convertono **solo** dentro una sequenza compitata, altrimenti "setup di gara" diventerebbe "setup d gara": la propagazione da un pezzo non ambiguo è transitiva. Dependency-free come `voice-intent.ts`, asserito da `spoken-name.selfcheck.ts`
- **track-map-builder.ts** — Derives a 2D SVG path of the circuit from a lap's world-space frames (wx/wz). Down-samples to ~100ms intervals, filters outliers, returns `TrackMapGeometry` (svgPath + bounds). Called after lap completion; result persisted to `track_maps` table
- **voice-coach.ts** — Handles free-form voice queries; streams Claude response in Italian (max 3-4 sentences, radio tone). Does **no DB access**: `main.ts` owns the session identity and pushes laps, setups and analyses in via `updateContext` before each query (resolved by id+game, so a reopened session gets its own data). Renders the most recent analysis in full (`synthesis` + `detail` + driver comments), older ones as their `summary`
- **voice-intent.ts** — Classifies a transcribed voice command: `classifyVoiceIntent(text, assistantName)` → `newSession` (with the game named in the phrase, `null` if absent or ambiguous) / `closeSession` / `analyze` / `acquireSetup` (i 4 trigger "acquisisci/carica/preleva/nuovo setup"; è deliberatamente l'**ultimo** ramo di comando, perché "nuova sessione" non è un setup e "valuta il nuovo setup" nomina un setup ma chiede un'analisi) / `greeting` (wake call by name) / `freeform` (question with the wake prefix stripped). Also exports `matchGame()` and the ten `GREETINGS` with `nextGreeting(count)`. Dependency-free on purpose (no DB, no IPC, no SDK) so `voice-intent.selfcheck.ts` can assert it without a simulator — the regexes used to live inline in `main.ts` untested
- **voice-summary.ts** — Owns the `<sintesi-vocale>` contract: `extractVoiceSummary()` / `stripVoiceTag()`. Dependency-free on purpose (no Anthropic SDK) so it stays self-checkable. The closing tag is optional — a Level-1 response truncated at `max_tokens` can open it and never close it, so the regex falls back to end-of-text rather than leaking raw tag markup into the rendered synthesis

## `tts/`

- **azure-tts.ts** — Azure Cognitive Services TTS REST wrapper (axios). Endpoints: voices list + synthesis + STT transcription. Applies `preprocessTTSText` from `shared/format.ts` (Italian number-to-words) before SSML escaping — the expansion itself lives in shared because the renderer's Web Speech fallback needs it too. Falls back gracefully if Azure is not configured

## `db/`

- **db.ts** — `better-sqlite3` wrapper. Schema has separate tables for each game (see the `db-schema` skill). Exposes `seedCornersFromLap()` (auto-generates "Curva N" corner names from braking zones), `getTrackMap()` / `saveTrackMap()` (track-map geometry cache)
- **r3e-corners.ts** — Auto-generated corner seed data for R3E tracks (sourced from sealhud). Do not edit manually. Used by `db.ts` to seed `corner_names`
- **setup-row.ts** — Shared DB helpers: `tableFor(game, base)` resolves game-specific table names; `parseSetupRow()` deserializes `setup_json`. Used by `main.ts` and `session-coach.ts`
